# Meshy 인물 캐릭터 작업 상태

2026-11-07 기준 Meshy CLI 0.8.3의 기기 로그인이 완료되었고 생성·리깅·애니메이션 API가 정상 동작합니다. 환경 설정 변경이나 게시 작업은 하지 않았습니다.

## 게임에 연결된 모델

| 슬롯 | 전신 외형 | 고유 스킬 동작 |
| --- | --- | --- |
| nova / 노바 | 흰 폴로, 검은 바지 | Punch Combo |
| blaze / 블레이즈 | 검은 후드 | Right Upper Hook from Guard |
| specs / 스펙스 | 검은 안경, 스웨트셔츠 | Counterstrike |
| volt / 볼트 | 검은 티셔츠 | Right Uppercut from Guard |

네 모델 모두 한 사람씩 분리한 전신 A포즈 참조로 생성했습니다. 참조는 사용자의 최신 네 사진을 보고 만든 이미지이며 원본 사진 픽셀은 아닙니다. 각 GLB에는 휴머노이드 리그와 여섯 동작(잽·훅·KO·도발·회피·고유 스킬)이 들어 있습니다. 최종 웹 자산은 무손실 텍스처 압축을 적용한 GLB입니다. 파일 크기와 해시는 `docs/meshy-assets.json`에 기록합니다.

`public/characters/models/manifest.json`에 준비된 네 모델, 실제 클립 이름, 작업 ID 및 모델에서 렌더링한 초상화 경로를 기록했습니다. 첫 생성에는 152크레딧을 사용했습니다. 이후 사용자가 네 명 모두 개선하는 추가 252크레딧을 승인했습니다. 두 번째 작업은 고해상도 모델 35, 리메시 5, 리깅 5, 여섯 애니메이션 18로 **1명당 63, 추가 총 252크레딧**을 사용했습니다. 누적 사용량은 **404크레딧**입니다. 승인 범위를 넘는 재시도는 하지 않았습니다. 작업 ID·실제 비용·파일 해시는 `docs/meshy-assets.json`에 보관합니다.

새 작업에는 Meshy 7.1 Ultra 4K 지오메트리와 4K PBR 텍스처를 사용했습니다. 원본 약 47만~74만 폴리곤을 웹 게임과 리깅에 맞게 약 12만 폴리곤으로 줄였습니다. 리메시 전후의 얼굴 렌더를 비교해 눈·코·입과 헤어·안경 특징이 유지되는지 확인했습니다. 이전 모델의 거친 얼굴 표면은 개선됐지만, 사진과 완전히 같은 얼굴이나 표정은 아닙니다.

웹 자산은 glTF Transform 4.5.1로 텍스처를 WebP 무손실 압축하고 사용하지 않는 데이터를 정리합니다. 원본과 압축 후 텍스처의 해상도 및 디코딩한 픽셀 일치를 검사합니다. 본과 애니메이션 이름도 유지하며 추가 디코더 없이 Three.js의 WebP 텍스처 지원을 사용합니다. 새 파일은 `*-hd.glb`, `*-hd-portrait.png`로 버전을 구분합니다. CLI 응답과 원본 다운로드는 공개 폴더에 넣지 않습니다. 최종 파일은 1명당 약 34~37MB이며 처음 선택할 때 다운로드가 필요합니다. 로드한 템플릿은 재사용합니다. 이전 공개 모델 파일은 비공개 작업 폴더에 백업한 뒤 제거했습니다.

검은 의상에 흰 균열처럼 보이던 부분은 텍스처 아틀라스 경계가 밉맵에서 섞이는 현상이었습니다. 네 모델의 텍스처 축소 필터를 `LINEAR`로 지정하여 자동 밉맵 생성을 끄고 경계 번짐을 수정했습니다. 텍스처 이미지 바이트와 애니메이션 목록이 그대로인지 확인했으며 재질의 금속성이나 색은 변경하지 않았습니다. 선택창 초상화도 최종 모델에서 다시 렌더링했습니다.

처음 보내신 네 명(`mint`, `ace`, `ink`, `stone`)은 기존 임시 모델입니다. 현재 폴더에 원본 사진이 없으며 새 인물 모델이 생성되지 않았습니다. 선택창에도 임시 모델로 표시합니다.

## 런타임 연결

- `src/assets/library.ts`: GLB 캐시 및 캐릭터별 스켈레톤 복제. 서로 다른 선수의 포즈를 독립적으로 유지합니다.
- `src/assets/native-clips.ts`: 실제 클립 이름을 게임 행동에 연결하고 루트의 수평 이동을 제거합니다. 위치 판정은 서버가 담당합니다.
- `src/assets/rig.ts`: 실제 클립을 우선 재생하고 행동별 속도를 맞춥니다. 기본 자세·이동·피격은 보완 클립을 사용합니다. 새 경기에서 상태를 초기화하며 교체 시 복제 스켈레톤을 정리합니다.
- `src/assets/gloves.ts`: 손 본에 복싱 글러브를 붙입니다. 스킨의 실제 손 정점 범위를 측정해 긴 손가락도 글러브 안에 들어가도록 크기와 위치를 맞춥니다.
- `src/assets/preview.ts`: 선택창의 회전 가능한 실제 3D 모델과 스킬 시연. 창을 닫거나 캐릭터를 바꾸면 렌더러를 정리합니다.
- `scripts/render-portraits.mjs`: 실제 GLB에서 선택창 초상화를 다시 렌더링하는 로컬 도구입니다. 개발 서버 실행 중 사용합니다.

## 렌더링

콘솔 메뉴에서 숨겨진 링과 그림자가 계속 그려지던 문제를 수정했습니다. 화면 크기가 0이거나 탭이 숨겨져 있을 때 링 렌더링을 생략합니다. 게임 판정이나 온라인 서버의 진행 시간은 바꾸지 않습니다. 소프트웨어 WebGL(SwiftShader·llvmpipe 등)에서는 그림자 렌더링을 줄이고 일반 GPU에서는 기존 그림자를 유지합니다. 전체 GLB를 읽는 동안에도 준비된 인물 초상화를 임시 모델에 사용해 누락된 SVG 요청을 방지합니다.

## 비용과 자료 보관

CLI는 `scripts/meshy.sh`를 사용합니다. 공통 JSON 옵션과 Node의 프록시 지원을 적용합니다. 자산을 쓰는 명령에는 `--workspace /workspace/BoxingCS`를 지정합니다.

새로운 유료 작업 전에는 공식 가격과 잔액을 확인합니다. 모델·리깅·애니메이션 제출 ID를 저장하고 동일 작업을 기다립니다. 실패나 품질 문제를 이유로 임의로 유료 재시도하지 않습니다. 내려받은 모델의 얼굴·전신·리그와 동작을 실제로 확인합니다.

원본 입력, CLI 메타데이터, 다운로드 영수증 및 서명 URL은 Git에서 제외된 `.asset-jobs/`에 보관합니다. 공개 폴더에는 GLB·PNG와 서명 URL이 없는 manifest만 둡니다. 인증 정보는 프로젝트와 채팅에 복사하지 않습니다.

## 최종 검증

온라인 공정성 보완 후 최종 실행에서 단위 테스트 **42개**, 배포용 서버를 사용한 실제 Chromium 브라우저 테스트 **16개** 및 TypeScript 검사·프로덕션 빌드가 모두 통과했습니다.

캐릭터와 대전 검증은 네 모델의 실제 3D 선택·스킬 시연, AI 전투, 모바일 메뉴, 팀 순서, 초대와 같은 참가자의 재접속 및 기권 결과 전달을 포함합니다. 오디오 검증은 첫 입력 후 음악 재생, 음소거 설정 저장, 경기 중 음악 정지, 실제 효과음 버퍼 재생과 메인 복귀 시 음악 재개를 포함합니다. 전체 검증 명령은 `npm test`, `npm run build`, `npm run test:e2e -- --workers=1`입니다.

온라인 검사에 도입했던 25초의 추가 상한은 서버의 30초 재접속 규칙보다 엄격하여 제거했습니다. 재접속 후 BLUE/RED 참가자가 같은 경기로 돌아오는지와 기권 결과가 상대에게 전달되는지를 검사합니다. 두 브라우저에서 고해상도 자산을 읽는 전체 흐름의 테스트 상한은 150초입니다. 게시와 공개 배포는 수행하지 않았습니다.
