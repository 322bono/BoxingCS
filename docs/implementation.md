# RING CLUB

사용자 선택: 3D 브라우저 복싱, 경기 중 1인칭 시점. 기존 저장소는 빈 저장소.

- Three.js + TypeScript + Vite, DOM 메뉴/HUD, Node/Express + Socket.IO.
- 서버 30Hz 고정 스텝: 이동, 사거리, 타격, 체력, 스태미나, 쿨다운 및 경기 종료 판정. 렌더링과 판정 분리.
- 로컬 AI는 같은 시뮬레이션 사용. 온라인은 단일 서버 메모리 로비.
- 초대코드 6자리. 1대1 또는 2~4인 팀. 모두 준비 후 방장 시작.
- 팀별 랜덤 팀장만 30초 동안 출전 순서 변경. 각 순번끼리 90초 대결, KO 또는 남은 체력으로 판정. 팀 승수 동률 시 첫 순번 선수 결정전.
- 연결이 끊기면 30초 대기, 세션 토큰으로 복귀. 시간 초과 시 기권. 서버 재시작 시 로비 초기화.
- 최신 네 사진은 전신 A포즈 참조를 거쳐 Meshy 모델·리그·여섯 동작으로 연결. 처음 네 명은 임시 초상화와 절차적 모델. 사진 원본이나 닌텐도 자산을 포함하지 않음.
- 캐릭터 성능은 외모와 독립적으로 파워/속도/회복을 상쇄 배분. 실제 플레이 데이터에 따른 추가 밸런스 튜닝 필요.
- 테스트: 판정/로비 단위 테스트, 실제 서버 복수 브라우저 통합 플레이, 모바일/데스크톱 캡처 및 빌드.

## 초기 밸런스 검증

동일한 클럽 AI 정책으로 시드 1~20, 양쪽 코너를 교대하여 총 240경기를 시뮬레이션했습니다. 캐릭터당 120경기 기준 모스 56.7%, 에이스 40.0%, 잉크 51.7%, 스톤 51.7% 승률입니다. 자동 회귀 기준은 캐릭터별 35~65%이며, 실제 사람의 조작 숙련도와 대전 데이터는 별도 검증이 필요합니다.

## 검토 후 수정

- 30초 이상 끊긴 로비 참가자를 정리하고 방장 권한을 이전합니다.
- 1대1은 무승부도 종료하며, 팀전만 동률 결정전을 진행합니다.
- 출전 순서 편집은 재접속 대기 여부와 무관하게 서버 시각으로 30초 마감합니다.

## 콘솔 UI 및 캐주얼 전투 개편

메인을 전체 화면 컬러 패널로 교체했습니다. 대전/팀 배틀/트레이닝을 고르면 대형 캐릭터 미리보기와 하단 초상화 목록, 성능, 스킬 정보를 보여주는 선택 화면을 거칩니다. 로비와 설정도 어두운 게임 UI로 통일했습니다.

타격 시 시각적인 45ms 히트 스톱, 짧은 카메라 반응, 섬광, 콤보 표시, 저음 효과음을 추가했습니다. 시뮬레이션은 히트 스톱 동안에도 계속되어 온라인 판정에는 영향을 주지 않습니다. Q 스킬은 게이지 100을 소비하며 서버에서 사거리, 가드, 회피, 쿨다운을 판정합니다. 모스는 가드 관통, 에이스는 긴 사거리, 잉크는 짧은 사거리와 높은 위력/긴 후딜, 스톤은 균형형입니다. 기본 위력에 캐릭터 파워 배율이 적용됩니다.

최신 네 명은 실제 GLB를 선택창과 전투에서 공유하며 캐릭터별 스킬 동작을 재생합니다. 선택창에서 모델 회전과 스킬 시연이 가능합니다. 필수 안내를 남기고 반복되는 문구를 줄였습니다.

최신 네 모델은 승인된 추가 252크레딧으로 고해상도 재생성·리메시·리깅·애니메이션을 완료했습니다. 얼굴 표면과 눈·코·입 디테일을 개선했으며 사진과 완전히 같은 얼굴은 아닙니다. 처음 네 명의 실제 인물 모델 생성은 로컬 원본 사진이 없어 미완료입니다. 기존 AI 밸런스 테스트는 기본 공격 성능을 검증하며, 사람의 스킬 활용에 따른 밸런스는 추가 플레이 검증이 필요합니다.

## 온라인 공정성과 공개 준비

- 이동은 두 선수의 같은 시작 위치를 사용하고, 피격에 따른 게이지와 가드 비용은 양쪽 공격 처리 후 적용합니다. 동시에 게이지가 100이 되거나 스킬을 교환할 때 좌석 순서에 따라 결과가 바뀌지 않습니다.
- `Room.sync`는 서버가 발급한 접속 세대, 준비한 선수 ID와 로딩 마감을 가집니다. 두 실제 선수만 준비를 알릴 수 있으며, 두 모델 로딩 후 공통 3초 카운트다운을 진행합니다. 60초 로딩 마감은 양쪽에 같은 규칙으로 적용합니다.
- 재접속 및 아직 살아 있는 소켓의 교체 시에도 새 접속 세대를 만들고 두 선수의 조작을 지웁니다. 현재 경기·접속 세대가 아닌 입력은 거부합니다. 브라우저는 온라인 상태에서만 volatile 입력을 전송합니다.
- Render 무료 단일 Node 웹서비스용 `render.yaml`을 사용하며 공개 주소는 `https://ring-club-boxing.onrender.com`입니다. Supabase는 향후 계정·전적 데이터에 적합하며 현재의 상시 Socket.IO 서버를 그대로 배포하는 대상은 아닙니다. 공개 HTTPS 주소에서도 실제 브라우저를 사용해 대전과 재접속을 검사합니다.
- 실제 공개 검사에서 느린 WebGL 초기화가 세션 재연결을 지연시켜 30초 복귀 시간을 넘기는 경우를 재현했습니다. 첫 서버 상태를 받은 뒤 그래픽을 초기화하고 최신 로비·경기 상태를 다시 표시하도록 수정했습니다. 그래픽이 아직 없을 때 준비 완료를 잘못 보내지 않으며, 서버에 연결할 수 없을 때의 로컬 AI 경로도 유지합니다.
- 로비의 `in-room` 스타일이 경기 진입 후에도 남아 링을 23% 불투명도로 표시하던 상태 전환을 수정했습니다. 온라인 경기와 AI 연습에 들어갈 때 로비 상태를 해제하며, 실제 두 브라우저 검사에서 양쪽 링이 원래의 불투명도로 표시되는지 확인합니다.

## 관중과 경기 긴장감

실제 CC0 관중 녹음 세 개를 사용합니다. 낮은 경기장 웅성거림을 반복하고, 실제 피격·연타·스킬·경기 종료에 따라 환호를 재생합니다. 강한 반응은 작은 반응을 대체하며 반복 스냅샷과 반응 대기 시간으로 소리가 겹쳐 쌓이지 않게 합니다. 관중은 전용 음량을 가지며 타격 순간에는 잠깐 작아집니다. 효과음 전체 음소거와 화면 숨김도 따릅니다.

로딩·재접속 대기에서는 관중을 멈추고, 복귀 시 과거 타격을 다시 환호하지 않습니다. 결과 화면에는 마지막 환호를 잠깐 남기되 서버의 반복된 종료 스냅샷이 그 소리를 취소하지 않도록 처리합니다. 내려받는 중 음소거·메뉴 이동·새 경기로 전환된 소리도 나중에 재생되지 않습니다.

기존 시계는 마지막 30초에 주황색, 10초에 붉은색과 짧은 경고 링벨로 바뀝니다. 체력이 낮으면 화면 가장자리에 위험 표시를 더합니다. 추가 패널 없이 기존 HUD를 쓰며 모션 줄이기와 피격 효과 설정을 존중합니다. 경기 판정과 방장 권한은 기존 서버 규칙을 유지합니다.
